Évaluer le moteur de planification

Évaluez les règles impératives, les priorités, la faisabilité et les limites de recherche sur un petit exemple Orchestrata.

Orchestrata vous aide à vérifier qu’un plan respecte les règles et tient compte des préférences. Dans cet exemple, deux tâches peuvent occuper les places 0 et 1. Chaque tâche peut occuper l’une ou l’autre, mais elles ne peuvent pas être à la même place. La place 1 est préférable pour la tâche A.

L’exemple utilise des données fictives et s’exécute en local. Ce site n’héberge pas l’API et n’accepte pas de fichiers. Pour exécuter l’exemple via HTTP, consultez le guide de l’API locale.

Exécuter l’exemple

Depuis la racine du dépôt Orchestrata, avec une version stable des outils Rust :

(cd backend && cargo run -p orchestrata-cli -- examples/assignment.json)

Le résultat contient values: [1, 0]. Les scores des règles obligatoires et des préférences sont tous deux à zéro. Les valeurs suivent l’ordre de la saisie : la tâche A occupe la place 1 et la tâche B la place 0. La règle et la préférence sont respectées.

Modifier un seul élément

Copiez l’exemple d’affectation dans backend/examples/preference-change.json. Dans la contrainte prefer_value de la tâche A, remplacez la value de 1 par 0. Relancez la même commande avec examples/preference-change.json. L’affectation attendue devient [0, 1] ; la règle obligatoire ne change pas.

Dans une nouvelle copie, ne laissez que l’option [0] aux deux tâches et conservez la règle des places distinctes. Dans une version dont les résultats exacts ont été vérifiés, la CLI renvoie null : aucune affectation ne convient à ces données.

Choisir ce que le modèle doit représenter

  • Rendez une règle obligatoire si son non-respect rend le plan inutilisable.
  • Utilisez une préférence si le plan reste utilisable même lorsqu’elle n’est pas satisfaite.
  • Supprimez une option si elle ne peut jamais être choisie.

Commencez avec un exemple que vous pouvez vérifier à la main. Comparez les affectations obtenues à celles que vous attendez, y compris pour un cas sans solution. Si la limite de recherche est dépassée, le résultat reste inconnu. Cela ne démontre pas qu’aucun plan valide n’existe.

Que souhaitez-vous planifier ?

Décrivez les tâches, les personnes ou le matériel concernés, les règles à respecter et votre façon de planifier le travail aujourd’hui. Utilisez un exemple fictif ou anonymisé. N’envoyez pas de données client.
