One rule. One preference.

Assign two overlapping jobs to two resources. The jobs must use different resources. If both can be covered, prefer resource 1 for Job A.

Problem definition

The domains are the same for both jobs: resource 0 or resource 1.

{
  "variables": [
    {
      "name": "job_a",
      "domain": [
        0,
        1
      ]
    },
    {
      "name": "job_b",
      "domain": [
        0,
        1
      ]
    }
  ],
  "constraints": [
    {
      "kind": "all_different",
      "variables": [
        0,
        1
      ],
      "hard_weight": 1
    },
    {
      "kind": "prefer_value",
      "variable": 0,
      "value": 1,
      "soft_weight": 3
    }
  ]
}

Run the checked-in fixture

cd backend
cargo run -p orchestrata-cli -- examples/assignment.json

Open the input file on GitHub

Why this plan wins

There are four possible assignments. Two assign different resources, but only [1, 0] also satisfies the preference. The expected hard and soft scores are both zero.

Blocked: [0, 0] would assign both jobs to the same resource, breaking the required rule.
