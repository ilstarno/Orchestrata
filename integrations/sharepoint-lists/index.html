Connector guide

Microsoft SharePoint Lists

Use a selected business list as a small, explicit planning input.

Data, actions and access

In Microsoft SharePoint Lists

View Microsoft’s Issue tracker list screen and template guide. The official screen shows Issue, Issue description, Priority and Status columns in an empty list. It is a source-system example, not an Orchestrata result.

Choose the columns that carry the decision

Select one site and list, then agree which internal column names and scalar values may enter planning. Display labels in the list are not a substitute for checking column definitions. For an issue-tracking workflow, agree how the approved issue, priority and status values map to the work your team wants to review.

The connector reads the selected definitions and rows. Review a proposed change against its exact row and mapped column with the named owner; an empty template does not provide planning records.

Workflow illustrations

Original Orchestrata illustrations with sample records. Title, Load and Ready are example internal field names agreed for one list.

What this connector does

Use a selected business list as a small, explicit planning input.

Data in scope

Read selected column definitions and scalar row values from one configured site and list. This is not a site-wide search or a document-library crawler.

Reads and changes

Read selected list data and review a typed request to change one mapped value. Agree the exact list, column and review owner.

Access to arrange

Grant access to the selected site or list and its approved fields. Consent, resource access and the account’s effective permissions must all match the intended scope.

What to check before relying on it

Confirm the actual column types, the mapping to planning data and the review owner. Obtain a separate permission for any change you approve.

Plan a scoped pilot

Start with the records and decision described above. Agree the permitted data, account access and review owner before any connection. Use the listed records, permissions and decision to define the scope.
