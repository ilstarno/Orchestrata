What this connector does

Turn a selected issue queue into work that a team can review.

Data in scope

Read selected issue fields and receive verified webhook notices. Notices identify a change to inspect; they are not permission to change a ticket.

Reads and changes

Read the selected issue queue, receive verified change notices and review proposed issue-property changes.

Access to arrange

Agree the projects, issue fields and read permissions. An administrator must configure any webhook and the verification needed to accept its notices.

What to check before relying on it

Issue priority does not establish staff availability. Review the exact proposed property value with the issue owner. Apply approved changes through your Jira workflow.

Plan a scoped pilot

Start with the records and decision described above. Agree the permitted data, account access and review owner before any connection. Use the listed records, permissions and decision to define the scope.

  • Sprint scope Choose which issues fit the team’s capacity after accounting for dependencies and existing commitments.
