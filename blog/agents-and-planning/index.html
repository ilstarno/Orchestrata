A staffing callout changes more than one shift

See what a classifier can extract and what the shift plan still has to check.

At 14:00, two stores each need two people on shift. A worker calls out. The North store still needs someone on the floor, and the worker who can cover it is already on the register at the South store. The absence changes more than one line on the schedule.

An agent can help turn “Find cover for the afternoon” into a request that a manager can review. That is a different job from finding an assignment that works. The agent can put the facts in order. The optimizer can check them against the rules. The manager decides whether the proposed change goes on the roster.

Make the request visible

Before looking for a replacement, write down what is changing and what stays fixed. In the two-store staffing example, the four shifts overlap. One keyholder is already fixed. Each shift has a list of people who are eligible to cover it. The only change is to take the unavailable worker off the two lists they were on.

An agent could prepare a short summary: “Four shifts still need cover. The North keyholder stays on duty. One worker is unavailable for the two shifts where they were eligible. Nobody can cover two shifts at once.” That gives the manager something specific to correct. If the original request says only “the afternoon” and there is no confirmed time, leave that fact unresolved rather than guessing. The optimizer can only check the schedule it is given.

Classify the request, not the answer

A language assistant can extract dates and candidate fields from a message. A classifier does a narrower job: it chooses one option from a fixed list. For a support message, an issue label might be billing, account_recovery, or needs_review; a separate field can capture the required support language. Neither field chooses a person or promises a response time.

For example, “Me cobraron dos veces. ¿Me pueden responder en español?” contains two facts a team might need: a billing issue and a request for Spanish. Turn those into explicit fields, keep the original message for review where appropriate, and send uncertainty or conflicting labels to a human. In this example Spanish is a requirement, not a preference. No model has selected an agent yet.

Now consider three queues that all need cover at once. The worked support-queue example starts after classification, with three queues and two eligible agent choices per queue. The optimizer checks assignments together because the same agent cannot cover two queues at once. The fixture records eight combinations and an assignment with no rule violations and no missed preference. It verifies the assignment step, not the accuracy of a classifier.

The distinction is useful even without a model. If the queue and language are already known, skip classification and send the checked fields directly to the optimizer.

Let the rules decide what is allowed

The person already working the South register is the only remaining option for the North floor. Moving them north would leave the South register empty, so the plan must fill both positions together.

PositionWhat changes after the callout
North keyholderStays with the person already assigned.
North floorGoes to the person previously assigned to the South register.
South registerGoes to a different eligible person.
South stockKeeps the original assignment.

The local solver checked 12 assignments for the original schedule and four for the callout. Both plans cover all four shifts without double-booking anyone. The adjusted plan misses two preferences and has a preference score of −8 instead of zero. That is not eight uncovered shifts or eight minutes of delay. It is the total penalty for the two preferences the new plan cannot keep.

This distinction matters. “Keep the original register assignment if possible” is a preference. “Do not put someone in two places at once” is a rule. If neither store has enough eligible staff, tell the manager that the submitted rules leave no valid assignment. Do not quietly relax a rule to produce a better-looking schedule.

Review the change before anyone acts

Put the original and proposed assignments side by side. Call out what moved, what stayed fixed, and which preferences were missed. A manager can then spot facts that were never in the request, such as travel between stores or whether a handover is possible. If a fact matters, add it to the model and run the comparison again.

Run the linked sample files locally and compare the results before making a staffing decision. To see the difference between a required rule and a preference on a smaller problem, try the worked assignment.
