Planning examples and recipes

Start with a reproducible assignment problem and see how example inputs can inform your own finite planning model.

A recipe describes a small planning scenario and the fields it uses. The runnable examples have sample data. Read the description, run the included JSON model, and compare the assignments with the expected result. The examples test specific decisions; they do not replace your scheduling or dispatch system.

ExampleWhat you can inspectWhat it does not establish
Field-service technician assignmentMatch overlapping appointments to separate technicians from a list of eligible people.Live dispatch, road routing, or a full-day staffing plan.
Two-store staffing what-ifCompare the baseline plan with a callout across two stores while keeping a fixed shift.Forecasting, calendar integration, or labor compliance.
Fleet pickup and delivery assignmentMatch jobs to vehicles that can carry the job's load and cover its time window.Construction of vehicle routes or cumulative multi-stop capacity.
Airport gate assignmentPlace overlapping flights at compatible available gates.Live arrivals, gate systems, or full airport planning.
Call-center staffingCover concurrent queues using basic language and skill eligibility.Forecasting call volume, service levels, or live workforce management.

Run a catalog fixture

With a checkout of the recipe catalog and a built orchestrata-cli on your path, run this from the catalog repository root:

orchestrata-cli recipes/examples/fleet-pickup-delivery/problem.json

The checked-in result has values [1, 2, 0], with zero hard and soft penalties. Read the accompanying inputs.json to see the business inputs and expected.json to compare the result. The XML describes the scenario; the CLI receives the normalized JSON model. The catalog repository contains source examples, not a versioned catalog package.

Use the assignment guide to run a smaller example without the catalog. Use a catalog example as a starting point: choose a decision, write down the allowed options, and model only rules you can verify. Do not send real customer or employee data into a local preview. Synthetic fleet workloads can generate repeatable stop inputs; the dataset generator does not route vehicles or estimate travel time.
