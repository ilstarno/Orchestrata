Developer guide / Local quickstart

Solve your first planning problem.

Give two jobs different assignments. Prefer one assignment for the first job, then see what the solver returns and why.

Start with the local API

The example

Decisions
Two jobs, two values
Hard rule
Use different values
Preference
Give job A the value 1

[1, 0]

01 / Run it

Start the development API

From the checkout root, with a current stable Rust toolchain:

(cd backend && cargo run -p orchestrata-api)

Send the bundled example

From the same directory in a second terminal:

curl -fsS -X POST http://127.0.0.1:3000/api/v1/solve \
  -H 'Content-Type: application/json' \
  --data-binary @backend/examples/assignment.json

To inspect the request schema, open /api/v1/openapi.json on the same local server. To run without HTTP, use the local CLI:

(cd backend && cargo run -p orchestrata-cli -- examples/assignment.json)

02 / Interpret it

Know what the answer proves

Found a solution

HTTP 200 with solution set. The example returns [1, 0] with zero hard and soft penalties. Values follow the order of the input variables.

Proved infeasible

HTTP 200 with {"solution":null}. Exact search found no assignment that satisfies every hard constraint in the submitted model.

Could not solve

Inspect the error. An invalid model, exceeded search cap, or execution failure is not proof that the model is infeasible.

03 / Boundaries

Start small, stay local

The exact solver enumerates at most 100,000 combinations through the shared service. Use finite integer domains and model every hard rule explicitly. The solver does not write assignments back to dispatch, ERP, or CRM systems.

This quickstart covers local HTTP and CLI usage. It is not a hosted deployment guide or a promise of native SDK support. Keep the development API on loopback.
